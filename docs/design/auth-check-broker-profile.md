# Auth Check broker profile

The broker has a release-owned `auth-check-worker-v1` profile for the isolated Auth Check worker. It permits only Bun running `/opt/nulltrace/workers/auth-check-worker.js`, one `auth-check-config` secret slot capped at 128 KiB, one normalized HTTP origin, a deadline no longer than 60 seconds, and output capped at 4 KiB. The broker rejects changed argv, slot declarations, origin shape, or resource limits before runtime admission.

The profile is added by `ExecutionBrokerHostService` only when a trusted `ExecutionCredentialAuthority` is injected into the host constructor. The daemon configuration loader does not provide this authority or enable the profile. The app/admin protocol cannot set a context generation, installation scope, or authority, and the admin grant API does not accept raw secret values. Authenticated execution remains unavailable in the packaged daemon until an owner-controlled authority and protected companion transport are integrated.

The broker resolves and durably stores the nonsecret scope/generation receipt from the trusted authorization ID and full plan. Before it stages the secret input, the broker checks the private config's context version against that receipt, its origin against the approved plan origin, and its worker deadline against the plan limit. It repeats current-generation validation after input staging and at commit-to-start. The supervisor repeats the private-input checks and clears its staged copy after use or cleanup.

Secret output stays withheld except for the Auth Check profile. The supervisor accepts one bounded newline-terminated JSON frame from stdout, validates the fixed primitive worker result schema and comparison semantics, then reserializes it. Any stderr, extra frame, malformed result, unsuccessful exit, cancellation, or uncertain cleanup discards the output. The broker exposes the event only after a normal zero exit, confirmed cleanup, durable settlement, an unrevoked receipt, and a current generation check. Other profiles with secret inputs cannot use this output path.

The future app adapter must use the existing broker receipt and event APIs; receipts do not reveal scope or generation. Its grant provider must issue authorization for this exact plan and reject stale context before returning an authorization ID. Callers cannot manufacture the broker binding.

## OrbStack qualification

The ARM64 OrbStack qualification exercises the broker, supervisor, isolated worker and network runtime with synthetic local receivers and generated in-memory canaries. It verifies the unauthenticated and authenticated requests reach the approved A origin, a positive-control request reaches B before the redirect check, an off-origin redirect leaves the B receiver at zero requests, stale context configuration is rejected before any receiver request, and revoking an active generation confirms cleanup while withholding its result. The canary scan found no match in captured Docker arguments or container command/environment metadata, proxy decisions, or retained result events. The temporary tools image was removed, with zero installation-labeled containers and networks remaining.

The evidence records OrbStack engine version and immutable worker, proxy and initializer image IDs at [orbstack-auth-check-broker-profile-arm64.json](../../infrastructure/isolation/evidence/orbstack-auth-check-broker-profile-arm64.json). This qualifies the broker profile on OrbStack Linux ARM64 with controlled receivers; it does not qualify the packaged daemon, application grant adapter, other tools, or other container engines.
