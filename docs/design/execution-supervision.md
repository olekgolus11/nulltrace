# Execution supervision and recovery foundation

This is an incremental implementation of [#161](https://github.com/olekgolus11/nulltrace/issues/161). It establishes cancellation, finite ownership and execution deadlines, installation-scoped recovery and a durable nonsecret outcome summary. It does not activate a tool migration or complete #161.

`HttpExecutionSupervisorService` implements the broker's existing runtime adapter for public HTTP plans with no input slots. It starts one run at a time, maintains an absolute deadline and a shorter renewable ownership lease, and passes one cancellation signal through resolution and the Docker execution boundary. The lease cannot extend the absolute deadline. An ordinary completion, cancellation, lease expiry or timeout is not considered clean until the worker and proxy environment has been removed. Failed cleanup blocks another start. Its memory-held result is intentionally only a bounded status and exit code; raw command output is not replayed by this service.

`HttpExecutionNetworkService` now requires an `ExecutionBrokerOwnershipLock`. The trusted broker must hold the `ExecutionBrokerLockService` on a private, stable installation path for its lifetime. This SQLite lock prevents a second live broker from reconciling the first one's engine resources. Every disposable container and network carries a trusted installation label. On startup the network service removes and verifies only resources with that label before starting another run. If the engine cannot be inspected or cleanup is uncertain, the backend remains locked until an explicit retry succeeds.

The broker receipt journal stores a separate outcome row containing only execution ID, terminal cause, exit code and cleanup condition. `ExecutionReceiptRepository.recordOutcome` commits the outcome with the cleanup receipt atomically. `ExecutionRecoveryService` confirms receipts only after installation-owned resources are absent. The `onSettled` callback must be wired to the receipt repository by the broker bootstrap. A failed callback blocks another run until settlement is retried. These records contain no command, URL, stdout, stderr, proxy log or secret.

The OrbStack ARM64 qualification now also creates a controlled orphan network and proves it is removed before the allowed request. It holds a real request open, cancels the running worker, and checks that execution-labeled container and network counts are zero. The existing allowed, redirect, direct bypass and DNS/IPv6 checks remain in place.

Remaining #161 work includes the private broker daemon/bootstrap, control API operations for cancel and lease renewal, bounded sanitized event transport, hostile artifact collection and application persistence, calibration of effective memory/CPU/PID/file limits, cancellation and restart tests across all lifecycle phases, and Docker Desktop qualification. Until these are implemented and qualified, this foundation must not be advertised as complete isolated execution in the TUI.
