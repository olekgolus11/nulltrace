# Isolated Auth Check worker

This worker is a bounded HTTP operation for the broker to invoke. It accepts one private input file containing the normalized exact target origin, verification URL, context version, authenticated headers, fixed per-request limits (10 seconds, 128,000 response bytes, five redirects), and a total deadline capped at 60 seconds. It performs the unauthenticated and authenticated GET legs in sequence from the same configuration. Only the authenticated leg receives the supplied headers; the worker keeps no cookie jar between legs.

The worker returns a versioned comparison result with each leg's HTTP status, redirect count, cross-origin-redirect flag, fixed content-kind category, and login-form boolean. It also returns fixed difference booleans, the comparison status, and a proceed bit. It never returns a URL, header value, response text, title, content hash, redirect path, or raw error. The result parser checks the schema, comparison rules, and combinations that cannot occur (for example, a redirect difference when neither leg redirected). These checks do not prove that worker-reported observations are truthful or that the worker was uncompromised. Auth Check remains an observation about response behavior, not proof of authorization scope.

HTML interpretation uses the repository's Cheerio behavior. A separate locked worker dependency directory pins Cheerio 1.2.0, matching the resolved application lock. The tools image bundles the worker at build time and retains dependency license notices under `/opt/nulltrace/licenses/auth-check-worker-deps/`; the running image does not install packages.

Every request uses Bun's explicit proxy option with the broker-provided proxy URL. The worker requires matching `HTTP_PROXY`, `HTTPS_PROXY`, and `ALL_PROXY` values and an empty `NO_PROXY`. It manually handles every 3xx response with a Location header to preserve the existing Auth Check redirect behavior. Same-origin redirects may continue; userinfo-bearing redirects fail; an off-origin redirect is reported without a request to that origin. Request and total deadlines cover response-body reads, and redirect/overflow cleanup does not wait on an untrusted stream's cancellation promise.

The explicit proxy setting is a compatibility control, not proof of containment. Network isolation must still prevent direct connections and constrain proxy egress. The A-to-B loopback test verifies only that this worker does not follow an off-origin redirect; its zero-hit B receiver does not qualify the firewall or proxy.

The broker now defines the fixed `auth-check-worker-v1` profile when its host is constructed with an injected trusted `ExecutionCredentialAuthority`. That profile restricts execution to the bundled worker, one exact HTTP origin, a 128 KiB private configuration slot, a 60-second deadline, and 4 KiB of output. The packaged daemon remains public-only because it does not receive that authority. The current `AuthCheckService` is still wired to its legacy host `fetch` path; it does not use this profile. Therefore the application adapter is **NOT IMPLEMENTED**, and this profile is not available to normal packaged application runs.

Before an application adapter can be enabled, it still needs an owner-controlled native companion identity and a trusted app-side grant provider, plus source-generation checks, revocation/cleanup handling, and conditional metadata persistence. It must be wired through the existing operator-triggered Auth Check workflow and preserve the existing inconclusive-result acknowledgement behavior. Worker comparison claims remain untrusted observations and cannot govern execution eligibility or override the app's comparison policy.
