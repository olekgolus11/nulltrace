# Use a broker and per-run HTTP network isolation

Status: accepted architecture; production implementation and platform qualification remain pending.

## Decision

Distribute NullTrace through Docker Compose on macOS with Docker Desktop and OrbStack as target runtimes. A dedicated, minimal execution broker uses the existing engine to create, supervise and destroy disposable execution environments. NullTrace and scanner/browser workers receive no Docker socket or network-administration authority. The broker exposes a narrow execution protocol; it does not forward arbitrary Docker API requests. Trusted release configuration owns images, mounts, capabilities, security profiles and resource ceilings. Operator-edited commands are execution inputs, never infrastructure options.

For each HTTP execution, create a separate worker, Squid instance and network policy. A short-lived infrastructure initializer installs nftables default-drop input/output/forward rules in the worker and proxy network namespaces. Only that initializer receives NET_ADMIN; it receives no Docker socket, application data or credentials and exits before untrusted processes start. The broker must verify effective policy before starting the worker and proxy. A failed or unverifiable setup destroys the environment; no host-execution or unrestricted-network fallback is permitted. Mount and PID namespaces remain separate. Do not change the shared desktop VM firewall to implement this profile.

Worker egress permits only its assigned proxy listener. Proxy egress separately permits the approved destination address/port tuples; Squid additionally checks approved hostnames, ports and HTTP/CONNECT intent. Namespace rules cover IPv4 and IPv6, including narrow required neighbor-discovery traffic. There is no blanket loopback exception, arbitrary worker DNS or reachability to other runs and control services. Proxy configuration and environment variables are additional controls, not the network boundary.

A trusted setup component resolves only approved names, validates all address results and supplies fixed per-run mappings to the proxy and firewall. Resolution does not itself authorize an address. Deny unauthorized loopback, link-local, metadata and private destinations; approved Mac/LAN/VPN targets require explicit address-and-port mappings, never broad private-network exceptions. Preserve the operator's origin, Host, SNI and certificate verification through those mappings. Changes requiring new addresses rebuild the validated policy rather than silently extending a running worker's scope. Detailed resolver/rebinding validation belongs to implementation and qualification.

## Trust and execution constraints

The broker and engine are trusted, high-impact components: broker compromise can expose other engine-managed resources and host files shared with Docker. A narrow broker API reduces client authority but does not remove the consequences of compromising the broker itself. We accept this installation tradeoff instead of requiring a separately provisioned rootless execution engine. The broker does not run scanner commands, browser content or model code in its own process/container. Its control interface is available only to the authorized application control plane and is not published to target-facing networks.

HTTP workers and Squid run as non-root users without capabilities, with no-new-privileges, seccomp, read-only root filesystems, private bounded writable storage and verified CPU/memory/PID/file/time limits. Apply enforcing AppArmor/SELinux policy where supported and record its absence where unavailable; never claim it is present without evidence. No home, database, credential-store or Docker-socket mounts are permitted in workers. Resource, output and artifact bounds, timeout/cancellation, crash recovery and cleanup are mandatory broker-contract requirements, not completed features of the experiment.

Preserve ADRs 0004 and 0007: only run-specific ephemeral secrets, owner-restricted files, exact-origin authentication, no secrets in argv/environment or exported logs/artifacts, and cleanup on every termination path. Credentials and authentication semantics require their own design and tests; a CONNECT allowlist cannot provide those guarantees alone. No automatic TLS MITM is introduced. An approved endpoint may itself relay traffic, and a compromised worker may disclose a secret it possesses to an approved endpoint; the network boundary limits reachable endpoints, not the trustworthiness of those endpoints.

Nmap uses a separate IP/port/protocol profile. Its raw-packet modes need enforcement outside the scanner namespace and separate validation; grant NET_RAW only where a validated mode requires it. No HTTP experiment proves Nmap containment. OpenCode remains a separate runtime and network policy, with controlled session-data access; scanner policy must not become general model Internet access. Existing disabled web tools are not enabled by this decision.

## Evidence and delivery gates

The [OrbStack experiment](../prototypes/http-isolation/RESULTS.md) passed 26 isolated-fixture checks and 28 checks in its Mac-loopback variant. Approved HTTP/HTTPS worked over upstream IPv4/IPv6. A controlled forbidden server recorded zero HTTP requests, DNS queries and input TCP/UDP packets after enforcement, including redirect and bypass attempts. This is evidence of pre-send prevention for those tested paths, not merely application detection. Effective PID/memory/CPU limits and normal/error cleanup were also observed.

The experiment is not a production broker or a NullTrace vertical slice. Docker Desktop, public/LAN/VPN routing, concurrent runs, resolver edge cases, startup races, all cancellation/crash/recovery paths, filesystem/credential canaries and other tool profiles remain qualification gates. Runtime support is not inferred from the other runtime's results. The accepted architecture may need revision if those experiments invalidate an assumption; unqualified configurations must not be advertised as supported or silently run without containment.

Implement shared infrastructure first, then migrate existing tools individually, beginning with cURL. Preserve the TUI, operator approvals, history, logs, artifacts and secret redaction. Playwright external resources, Nuclei auxiliary protocols/services, secret persistence and OpenCode integration retain their separate decision tickets; this ADR does not silently narrow existing behavior or authorize new features.
